## 1. 需求概述

### 1.1 系统定位

将现有闲鱼客服机器人系统作为底层消息接入层，全新构建酒店预订业务。

### 1.2 核心功能

| 功能 | 说明 |
|------|------|
| 查价 | 实时查询酒店价格并返回给用户 |
| 下单 | 用户确认后创建订单 |
| 状态同步 | 用户在外部完成支付后同步状态 |

### 1.3 需求矩阵

| 维度 | 选择 | 说明 |
|------|------|------|
| 系统定位 | B | 新建酒店预订业务，闲鱼系统作为消息接入层 |
| 预订范围 | C | 查价 + 下单，支付走外部渠道 |
| 订单状态 | 轻量 | 用户在外部支付后同步状态，本地只记录 |
| 查价方式 | A | 实时查询（后期可能升级缓存） |
| 多账号 | A | 单账号 |
| 规模 | B | 中等（100-500用户，20-100单/天） |
| 缓存 | 暂不加 | 使用 SQLite + 内存缓存 |
| 消息队列 | 暂不加 | 同步调用足够 |

## 3. 数据模型

### 3.1 订单表 (orders)

```sql
CREATE TABLE orders (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    order_id TEXT UNIQUE NOT NULL,        -- 订单唯一标识
    chat_id TEXT NOT NULL,                 -- 闲鱼对话ID
    user_id TEXT NOT NULL,                 -- 用户ID
    item_id TEXT,                          -- 闲鱼商品ID

    -- 酒店信息
    hotel_id TEXT NOT NULL,                -- 酒店ID
    room_id TEXT NOT NULL,                 -- 房型ID
    check_in_date TEXT NOT NULL,           -- 入住日期 (YYYY-MM-DD)
    check_out_date TEXT NOT NULL,          -- 离店日期 (YYYY-MM-DD)
    room_count INTEGER DEFAULT 1,         -- 房间数量

    -- 价格信息
    original_price REAL,                   -- 原始价格
    final_price REAL,                      -- 最终价格
    currency TEXT DEFAULT 'CNY',          -- 货币

    -- 状态管理
    status TEXT NOT NULL DEFAULT 'PENDING',
    -- 状态流转: PENDING → CONFIRMED → PAID → BOOKED → COMPLETED
    --                    → REFUNDED → COMPLETED

    -- 时间戳
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    confirmed_at DATETIME,                 -- 确认时间
    paid_at DATETIME,                      -- 付款时间
    booked_at DATETIME,                    -- 预订成功时间
    completed_at DATETIME,                 -- 完成时间

    -- 扩展字段
    metadata TEXT,                         -- JSON扩展信息
    remark TEXT                            -- 备注
);

CREATE INDEX idx_orders_chat_id ON orders(chat_id);
CREATE INDEX idx_orders_status ON orders(status);
CREATE INDEX idx_orders_created_at ON orders(created_at);
```

### 3.2 订单状态说明

| 状态 | 说明 | 触发条件 | 可转为 |
|------|------|----------|--------|
| `PENDING` | 等待确认 | 询价后生成（默认超时30分钟） | `CONFIRMED`, `EXPIRED` |
| `CONFIRMED` | 用户已确认 | 用户确认预订 | `PAID`, `CANCELLED` |
| `PAID` | 用户已付款 | 用户告知已付款 | `BOOKED`, `CANCELLED`, `REFUNDED` |
| `BOOKED` | 预订成功 | 酒店确认预订 | `COMPLETED` |
| `REFUNDED` | 已退款 | 退款成功 | `COMPLETED` |
| `COMPLETED` | 订单完成 | 用户确认/取消/过期 | - |
| `EXPIRED` | 已过期 | PENDING 状态超过30分钟未确认 | - |
| `CANCELLED` | 已取消 | 用户主动取消 | `COMPLETED` |

### 3.3 状态流转图

```
┌──────────┐     用户确认      ┌───────────┐
│  PENDING │ ──────────────→  │ CONFIRMED │
└──────────┘                   └───────────┘
    │                              │
    │ 超时30分钟                    │ 用户告知已付款
    ▼                              ▼
┌─────────┐                  ┌───────────┐
│ EXPIRED │                  │   PAID    │
└─────────┘                  └───────────┘
    │                              │
    │                         ┌────┴────┐
    │                         ▼         ▼
    │                    ┌────────┐ ┌──────────┐
    │                    │ BOOKED │ │ CANCELLED│
    │                    └────────┘ └──────────┘
    │                         │         │
    │                         │    退款成功
    │                         │         ▼
    │                         │   ┌──────────┐
    │                         │   │ REFUNDED │
    │                         │   └──────────┘
    │                         │         │
    │                         └────┬────┘
    │                              │
    │                        用户确认取消
    │                              │
    └──────────────────────────────┘
                              │
                              ▼
                         COMPLETED
```

## 4. 业务流程

### 4.1 询价流程

```
sequenceDiagram
    participant U as 用户
    participant X as 咸鱼Agent
    participant D as 对话Agent
    participant P as 价格服务
    participant H as 酒店执行器

    U->>X: 询价(酒店/日期/房型)
    X->>D: 转发

    D->>P: 查价请求
    P->>H: 调用酒店API
    H-->>P: 返回价格
    P-->>D: 返回价格信息

    D->>X: 返回价格
    X-->>U: 展示价格
```

### 4.2 下单流程

```
sequenceDiagram
    participant U as 用户
    participant X as 咸鱼Agent
    participant D as 对话Agent
    participant O as 订单服务
    participant H as 酒店执行器

    U->>X: 确认预订
    X->>D: 转发

    D->>O: 创建订单(PENDING)
    O-->>D: 返回订单

    D->>O: 更新订单(CONFIRMED)
    O-->>D: 确认成功

    D->>X: 返回确认成功
    X-->>U: 等待付款

    U->>X: 已付款
    X->>D: 转发

    D->>O: 更新订单(PAID)
    O-->>D: 付款确认

    D->>H: 执行下单
    H-->>D: 下单成功

    D->>O: 更新订单(BOOKED)
    O-->>D: 完成

    D->>X: 返回成功
    X-->>U: 预订成功
```

### 4.3 退款流程

```
sequenceDiagram
    participant U as 用户
    participant X as 咸鱼Agent
    participant D as 对话Agent
    participant O as 订单服务
    participant H as 酒店执行器

    U->>X: 申请退款
    X->>D: 转发

    D->>O: 查询订单

    D->>H: 执行退订
    H-->>D: 退订结果

    D->>O: 更新订单(REFUNDED)

    D->>X: 退订成功，请确认取消
    X-->>U: 通知用户

    U->>X: 确认取消
    X->>D: 转发

    D->>O: 更新订单(COMPLETED)
    D->>X: 返回完成
    X-->>U: 订单已取消
```

## 5. 模块设计

### 5.1 对话层 (Dialog Layer)

**DialogAgent** 职责：
- 接收来自接入层的消息
- 进行 NLU 处理（意图识别 + 实体提取）
- 管理对话状态
- 调用业务层服务
- 生成回复内容

**NLU 模块** 负责：
- 意图分类（询价、确认、下单、退款、取消等）
- 实体提取（酒店名称、入住日期、退房日期、房型等）
- 槽位填充

**状态机** 负责：
- 管理当前对话状态
- 判断是否可以进行下一步操作
- 处理订单状态相关的对话

### 5.2 业务层 (Business Layer)

**PriceService (查价服务)**
- 接收查价请求
- 调用执行层获取价格
- 返回价格信息

**OrderService (订单服务)**
- 创建订单
- 更新订单状态
- 查询订单
- 订单历史管理

**RiskService (风控服务)**
- 限流控制
- 黑名单检查
- 风险用户标记

### 5.3 执行层 (Execution Layer)

**HotelExecutor (酒店执行器)**
- 封装酒店API调用
- 处理下单请求
- 处理退订请求
- 错误处理和重试
